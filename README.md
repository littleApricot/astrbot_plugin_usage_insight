# 用量与费用明细

为 AstrBot 4.29.1 增加用量、费用与官方余额页面，查看缓存命中、模型和个人用量、费用估算及账户余额。机器人可用 `get_usage_stats` 查询近期总花费与成员排行，用 `get_self_balance` 查询账号余额；复用已有配置。

## 安装和打开

在 AstrBot 插件管理中刷新 littleApricot 的共享源，找到“用量与费用明细”并安装；也可以上传 ZIP 安装包：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

也可以使用以下仓库地址安装：

```text
https://github.com/littleApricot/astrbot_plugin_usage_insight
```

启用插件后，在插件详情的页面入口打开 `usage`。此页使用 AstrBot 自带的登录和插件页面桥接。更新时保留插件数据；插件启用前的旧记录不会获得新的个人归属信息。

### 从“自查余额”迁移

原 `astrbot_plugin_self_balance` 已合并到本插件。先在插件管理中卸载旧“自查余额”，再更新本插件至 v0.3.0 或更新版本。旧插件没有独立配置和数据库；本插件已有的用量数据库会保留。卸载旧插件可以避免宿主重新加载两个同名工具时互相覆盖。

机器人仍使用同一个 `get_self_balance` 工具名，无需修改原有称呼或工具使用提示。当前回复模型需支持工具调用，并允许使用该工具；说“查一下你还有多少余额”即可。原插件源只保留合并后的安装入口。

## 可以看到什么

- 总 token、输入和输出的数量与占比。
- 输入缓存命中率、缓存明细覆盖率、缓存节省金额估算。
- 模型调用次数、异常次数、平均耗时和每日 token 趋势。
- 按人、按模型、按用途和按群聊的汇总，以及分页调用明细。
- 今天、近 7 天、近 30 天和全部已采集数据；可按模型、用途和个人筛选。
- DeepSeek 官方接口自动同步人民币价格，按请求时间区分高峰和空闲时段；支持可选的手动价格覆盖。
- 分别列出未计价的原因，以及宿主历史、后台公共开销和未识别触发者的记录。
- 官方账号余额、充值和赠金余额，以及当前 API Key 在此 AstrBot 中的独立用量与费用估算。
- 机器人查询近期总 token、人民币费用估算、全部成员排行及压缩开销。

## 官方账号余额与本机 Key 用量

页面和 `get_self_balance` 共用 DeepSeek 官方查询、15 秒缓存和本地快照。同一个 Key 配置的多个提供商合并查询和展示，连续手动刷新在 2 秒内复用结果。默认启动时及每 300 秒采样一次；页面“刷新官方余额”可主动查询。页面普通读取只看已保存快照，不额外请求官方。

查询对象为已配置的 DeepSeek 官方提供商，工具调用优先使用当前事件选定的提供商，否则读取当前会话使用的模型。仅向 `GET https://api.deepseek.com/user/balance` 发送请求，复用该提供商当前 Key 和代理。只接受 HTTPS 官方主机及标准端口，禁止把 Key 发给其他平台或重定向地址。查询过程不调用生成模型。参见[官方余额接口](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/)。

页面分别展示官方账号余额与本 bot 当前 Key 的用量和估算。余额属于整个 DeepSeek 账号，同账号的其他 agent 会影响它；余额读取独立于下方统计筛选。本机 Key 用量按页面时间范围汇总，只包含此 AstrBot 实际采集且能确定凭据的请求，按所用价格估算费用。不同 Key 的调用分别统计，同 Key 的多个提供商合并。原始 Key 不保存，新调用使用带本地随机盐的不透明标记关联；请求期间 Key 切换时不猜测归属。旧记录没有 Key 标记，单独提示未归集数量，不能补造归属。

页面“本 bot 与其他应用”按来源分别显示：本 bot 一行展示当前 Key 在此 AstrBot 中采集到的调用、token、缓存和费用估算；同账号其他应用一行的调用、token 和花费均显示为“未知”。即使其他应用使用相同 Key，也无法通过本机记录看到它们的请求。账号余额属于整个账户，因此余额变化不能减去本 bot 的估算来推导其他应用花费。多个不同 Key 可能属于同一账号，页面各组账号余额不要相加。

查询失败保留上次成功账号余额和查询时间，并标明最近失败；没有成功快照时余额未知，不按零处理。关闭自动采样后，页面手动查询和机器人工具仍可使用。

### 机器人余额工具

`get_self_balance` 无业务参数，查询当前会话所选提供商对应的账户。成功时只返回人民币总可用余额的十进制数值，单位元，例如 `12.34`；零余额返回对应的零金额。

无法查询或未取得人民币余额时返回“未知”。余额仍由官方查询与短期缓存提供，账号余额属于整个账户，查询后可能随调用发生变化。工具结果由 AstrBot 正常记录在工具往返中。

### 机器人花费查询工具

`get_usage_stats` 只接收天数，查询本 bot 在这段时间已采集的用量和全部成员排行。统计排除 Codex CLI 识图和百炼直连判断，其余调用按已知 token 和人民币费用汇总；DeepSeek 的识图和判断仍计入。日期按 bot 配置时区的自然日计算，包含今天；金额为人民币估算，单位元。查询只读取本地统计，不调用生成模型或余额接口。

| 入参 | 默认值 | 含义 |
| --- | --- | --- |
| `days` | 7 | 整数天数，范围 0～36500；1 为今天、30 为近 30 天、0 为全部已采集数据 |

| 返回字段 | 含义 |
| --- | --- |
| `total_tokens` | 纳入统计的调用中，已知 token 的合计，含输入和输出 |
| `total_cost` | 纳入统计的调用中，已知人民币估算花费的合计，单位元 |
| `people` | 纳入统计的全部成员，按已知人民币花费降序；每项包含 `name`、`tokens`、`cost`，缺失数据时附加下述标记 |
| `compression` | 可选，有已分类压缩记录时返回 `tokens` 和 `cost`；已包含在总计中，单独展示 |
| `incomplete` | 可选，总计、成员或压缩项中不完整的字段列表：`tokens`、`cost`；顶层分别对应 `total_tokens`、`total_cost` |
| `failed_without_usage` | 可选，对应范围内失败、超时或取消且缺少用量回执的记录数；只在非零时返回 |

个人按触发者归属整轮上下文开销，同名成员保留独立条目。同额时按 token 降序排列。总额包含后台调用，记忆整理、历史未归属等公共用量计入总额。上下文压缩按公共开销分类，不摊给个人；因此总额可能高于个人排行之和。

部分记录缺失时仍返回已知合计，并用 `incomplete` 标记；例如一次成功调用加一次没有回执的超时，返回成功调用的 token 和费用，同时标记两项不完整及 `failed_without_usage: 1`。失败但已取得用量和人民币价格的调用照常计入，不标为缺失。异常记录的未知部分不能当作免费，是否实际扣费以平台账单为准。

只有整个范围都没有已知 token 或人民币金额时，对应值才为 `null`。完全未知金额的成员排在已知金额之后；已知部分按金额排序，显式免费计价可以返回零。排除指定来源后没有记录时返回零总计和空成员列表，含义限于纳入统计的已采集数据。

从 v0.7.0 起，LCM 压缩调用在转入异步子任务前绑定用途，后续新记录可单独统计；旧记录缺少压缩标记的部分保留原归属。工具仅返回上述字段。网页继续保留全部来源的记录，提供调用、缓存、归因和价格等完整指标；上述来源排除仅用于机器人工具的统计。

## 用量与费用口径

### 按人的口径

默认“按触发者”：某次触发后产生的多次模型调用都归给触发这次回复的人，包含同一轮中的工具往返。完整上下文的输入开销也包含在这次调用中，因此它不等于这个人自己打字消耗的 token。

“批次参与者均摊”读取回复判断插件实际合并的消息批次，按参与者的唯一用户数均分。一个人连发多条不会重复增加其份额。个人筛选返回该人的份额，全部人的份额加共享部分等于总量。这是统计分摊方式，不代表平台给每个人单独计费。

“宿主历史（未记录用户）”是启用插件前导入的整轮统计，原始数据没有用户字段，无法补出个人归属。“后台公共开销”包含上下文压缩，以及没有个人触发者的记忆整理和识图；其他缺少触发者的调用显示为“未识别触发者”。各类均可单独点击筛选。用户以平台实例加用户 ID 区分，昵称仅供显示；同名用户不会自动合并。已存明细保留当时的昵称。

### token 与缓存口径

只读取接口实际返回的 usage，不根据文字长度猜 token。优先读取原始响应里的缓存字段，兼容 DeepSeek 的 `prompt_cache_hit_tokens` 和 OpenAI 的 `prompt_tokens_details.cached_tokens`。推理 token 已包含在输出总量中时，不再加一次。

缓存命中率 = 已报告的缓存输入 token / 具有缓存明细的输入 token。缓存字段缺失时记为未知；页面同时显示缓存明细覆盖了多少输入，避免把部分可见数据当成完整命中率。宿主归一化 usage 中的默认零不能证明接口报告过零命中。

流式调用优先采用最后一个完整响应的 usage，避免把流末尾汇总与中间片段相加。仅收到片段时按 AstrBot 的片段 usage 契约累加。异常和取消仍保留调用记录，未返回的 token 和费用记为未知。

### 自动价格和峰谷时段

连接 `api.deepseek.com` 时，自动采用[DeepSeek 官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，支持 `deepseek-flash`、`deepseek-v4-pro` 及官方仍接受的 Flash 旧名。中转接口的价格不自动套用官方价。插件启动时和此后每 24 小时读取一次公开价格网页，不使用 API Key，也不发起模型调用。页面“模型价格”中可查看来源、核对时间和价格表，并手动同步。同步失败或官网结构变化时保留上次可用价格；初次联网前可使用随版本附带的官方价格快照。

北京时间周一至周五 9:00–12:00、14:00–18:00 为高峰，其余时段、周末和中国节假日为空闲，空闲价为高峰价的一半。按请求开始时间计算，跨过时段边界的请求仍使用开始时段。节假日历目前覆盖 2026 年，按[国务院年度放假安排](https://www.beijing.gov.cn/zhengce/zhengcefagui/202511/t20251104_4258873.html)中的放假日期处理；调休上班的周末仍按官方“周末全天空闲”规则处理。未收录年份的工作日潜在高峰时段显示“缺少该年节假日历”，不猜测该日是否放假。

新采集记录保存采用的官方单价、时段和价格核对时间，后续同步不会改变这批记录的估算。旧记录没有当时的价格快照，根据当前提供商配置和当前官方价回算，并在明细中标记；历史整轮优先使用宿主保存的整轮开始时间，缺失时才用记录时间，无法区分同一轮内跨时段的多次调用。它不能还原旧时的实际扣款。

### 费用口径和手动覆盖

价格单位均为每百万 token。DeepSeek 官方接口无需填写单价；其他接口、特殊折扣可在页面“手动覆盖”填写提供商 ID、精确模型名、货币代码、未命中输入价、缓存输入价和输出价。提供商 ID 留空表示适用于同名模型；指定提供商的规则优先。手动覆盖高于自动单价，保存后按固定价格重新计算匹配的已保存记录，移除后恢复自动价格。允许显式配置零价格，不把缺少价格自动视为免费。

估算金额 =（未命中输入 × 输入价 + 缓存输入 × 缓存价 + 输出 × 输出价）/ 1,000,000。缓存拆分未知且两种输入价不同时，该条费用不能估算；两种输入价相同则无需拆分即可计算。

页面金额仅包含可估算记录，并显示计价覆盖数。未计价记录分别说明缺少用量、缺少缓存明细、未匹配价格或缺少该年节假日历。不同货币分别汇总，不自动换汇。金额是基于报告用量和所选单价的估算，不能当作实际扣款；阶梯折扣、赠金和供应商账单调整仍以平台账单为准。

手动覆盖保存在插件配置的 `prices_json` 中，页面编辑与插件配置编辑共用同一个值。默认 `[]` 保留自动价格。每条手动规则的完整字段如下：

| 字段 | 要求 | 含义 |
| --- | --- | --- |
| `provider` | 可留空 | AstrBot 提供商 ID；直连判断接口使用 `bailian-decision` |
| `model` | 必填 | 接口调用使用的精确模型名 |
| `currency` | 默认 CNY | 三位货币代码，例如 CNY、USD |
| `input` | 必填、非负数 | 每百万未命中输入 token 价格 |
| `cached` | 必填、非负数 | 每百万缓存输入 token 价格 |
| `output` | 必填、非负数 | 每百万输出 token 价格 |

## 采集范围和历史

启用后观察 AstrBot 文本/视觉 Provider 的普通和流式调用，包括正式回复、图片回复判断、后台记忆整理、LCM 上下文压缩和通过 Provider 的识图。识别已加载插件和模型提供商，插件加载后或正式请求到来时刷新接入。

对本系列回复判断插件的直接 aiohttp 决策请求，尝试读取原响应的标准 usage 字段，不另发请求。当前 Codex CLI 识图采集只记录调用次数、耗时和状态，未采集 token 或按次金额。两类记录仍在网页中保留，缺失费用不算免费。外部 MCP 内部调用的模型、嵌入、重排和语音服务的账单不在此采集范围内。

模型调用次数按适配器调用计数，适配器内部网络重试不另计。某次失败请求是否在平台扣费，以账单为准。各用途归类对接当前本系列插件，未知来源保留在“其他调用”。

首次加载时读取开始采集时间之前、最近 `history_days` 天的 AstrBot `provider_stats`。这只导入已保存的整体 token、模型、来源和耗时，一条宿主记录是一轮 Agent 回复，可能包含多次模型调用，所以单独统计“历史轮数”，不假装它是一次调用。缓存明细未被宿主保存时无法补出；历史零缓存值按未知处理。重复加载按原记录 ID 去重，新采集数据与历史时间段分开。

导入期间页面显示进度状态；失败时保留已成功导入部分并记录错误类型，下次加载重试。插件停用期间不进行详细采集，重新启用不会补造停用期间的个人记录。详细采集开始时间和历史导入状态都在页尾显示。统计读取在独立线程中进行，不在回复链中扫描历史。

## 配置与数据

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` | true | 是否采集新的模型调用，已有数据仍可查看 |
| `prices_json` | `[]` | 可选的手动价格覆盖；DeepSeek 官方接口默认自动计价 |
| `history_days` | 365 | 启动时读取首次采集开始前多少天的宿主统计，范围 1～36500 |
| `balance_auto_refresh` | true | 自动采样官方余额；关闭后手动查询和工具仍可使用 |
| `balance_interval` | 300 | 余额采样间隔，单位秒，范围 30～86400 |

记录保存在 `data/plugin_data/astrbot_plugin_usage_insight/usage.sqlite3`，包含用量、模型、用途、时间、来源、触发者标识及昵称、批次参与者、异常类型、接口主机名、采用的官方单价快照和不透明的凭据标记。余额快照和凭据标记的本地随机盐也保存在此库。不保存提示词、消息正文、图片、密钥、请求头或原始模型响应。公开价格缓存保存在同目录的 `deepseek-prices.json`；同步只向固定的 DeepSeek 官方网页发起普通读取，不上传统计记录。升级保留数据库。

统计采集保持原有模型调用、判断结果和回复流程；新增余额工具按宿主工具流程返回结果。采集写入失败只记录错误类型，原调用继续返回。卸载时停止余额采样和价格同步，恢复本插件安装的观察函数，正在完成的模型调用写入后关闭数据库。

## 验证

在仓库目录运行（将路径换成自己的 AstrBot 源码目录）：

```bash
ASTRBOT_SOURCE=/path/to/AstrBot
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="$ASTRBOT_SOURCE:$PWD/.." \
  ASTRBOT_ROOT=/tmp/usage-insight-test \
  "$ASTRBOT_SOURCE/.venv/bin/python" -m pytest tests -q
```

自动检查覆盖原始缓存字段、未知值、费用公式、分母、按人分摊、共享费用、实际宿主统计表的历史导入与去重、配置保存、流式汇总、并发事件归属、直连判断采集、统计写入失败隔离和卸载恢复。价格检查覆盖峰谷边界、周末、节假日、调休周末、未知年份、自动价与手动覆盖、价格快照、同步失败和缓存恢复。实际运行 AstrBot OpenAI 适配器并模拟 SDK 返回，以检查复制 Provider 和 `wait_for` 任务路径中的采集。测试不调用付费模型、不发 QQ 消息。
